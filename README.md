# AI_PROMPTS.md — Промпти для розробки лабораторної роботи

Цей документ містить послідовність промптів для використання AI-асистентів під час реалізації лабораторної роботи з паралельного програмування.

**Технології:** Java, Go, MPI.

**Призначення:** забезпечити поетапну розробку, тестування, оптимізацію та документування програм.

## Загальні правила для AI-агентів

Перед початком роботи:

1. Проаналізуй наявні файли проєкту.
2. Не видаляй і не перезаписуй робочий код без необхідності.
3. Дотримуйся наявної архітектури або обґрунтуй її зміну.
4. Не вигадуй API, результати тестів та бенчмарків.
5. Не підмінюй MPI звичайною багатопоточністю.
6. Не переходь до наступного етапу без перевірки попереднього.
7. Після кожного етапу документуй зміни.
8. Не стверджуй, що операція успішна, якщо її фактично не виконано.

# Етап 3. Реалізація завдання №1

Реалізуй алгоритм обчислення суми масиву методом поділу на частини.

Основний розмір — 1 000 000 000 елементів.

Java:
1. Sequential.
2. Thread.
3. ExecutorService.
4. ForkJoinPool.

Go:
1. Sequential.
2. Goroutines + WaitGroup.
3. Goroutines + Channels.
4. Worker Pool.

Алгоритм:

1. Створити масив.
2. Розділити його на частини.
3. Передати кожну частину робочому потоку.
4. Обчислити локальні суми.
5. Дочекатися завершення всіх потоків.
6. Об'єднати проміжні результати.

Використовуй:
- `long` у Java;
- `int64` у Go.

Вимоги:
- відсутність Race Conditions;
- коректний поділ із залишком;
- відсутність переповнення;
- фіксована кількість робочих потоків;
- однакові тестові дані.

Додай параметри командного рядка:
- розмір масиву;
- кількість потоків;
- seed;
- режим запуску.

Додай автоматизовані тести.

Після реалізації:
- скомпілюй Java;
- збери Go;
- запусти тести;
- перевір однаковість результатів.

Не переходь до наступного етапу, поки код не проходить доступні перевірки.

# Етап 4. Реалізація завдання №2

Реалізуй хвилевий алгоритм здвоювання.

Не замінюй його звичайним Reduce.

Приклад:

```text
[1, 2, 3, 4, 5, 6]

Хвиля 1:
[7, 7, 7]

Хвиля 2:
[14, 7]

Хвиля 3:
[21]
```

Формули:

```text
partnerIndex = currentLength - 1 - index

array[index] += array[partnerIndex]

newLength = (currentLength + 1) / 2
```

Java:
- Sequential;
- Thread Pool;
- ExecutorService;
- ForkJoinPool.

Go:
- Sequential;
- Goroutines + WaitGroup;
- Worker Pool;
- Channels.

Особливу увагу приділи:
- непарній довжині;
- збереженню центрального елемента;
- синхронізації між хвилями;
- відсутності подвійного додавання;
- відсутності одночасного запису в один індекс.

Використовуй фіксовану кількість робочих потоків.

Робочі потоки повинні повторно використовуватися між хвилями.

Перевір алгоритм на невеликих масивах, включно з непарною кількістю елементів.

Порівняй результат із послідовною сумою.

Після реалізації запусти всі доступні тести.

# Етап 5. MPI та налаштування кластеру

Реалізуй MPI-частину лабораторної.

Необхідно забезпечити розподілені обчислення для обох алгоритмів мовами Java та Go.

Спочатку перевір сумісність бібліотек із встановленою реалізацією MPI.

Не використовуй вигаданий API.

Завдання №1:

- розподілити масив між процесами;
- обчислити локальні суми;
- об'єднати результати через MPI.

Використовуй відповідні операції:
- MPI_Init;
- MPI_Comm_rank;
- MPI_Comm_size;
- MPI_Scatter або MPI_Scatterv;
- MPI_Reduce;
- MPI_Finalize.

Завдання №2:

- розподілити індекси пар між процесами;
- обчислювати симетричні індекси;
- обмінюватися необхідними даними;
- формувати актуальну частину масиву;
- синхронізувати кожну хвилю;
- повторювати до отримання одного елемента.

Підготуй:
- конфігурацію вузлів;
- SSH;
- hostfile;
- налаштування MPI;
- команди компіляції;
- команди запуску.

Перевір локальний запуск із декількома процесами.

Якщо доступний кластер — виконай багатовузловий запуск.

Не називай локальний запуск багатовузловим тестом.

Якщо певна інтеграція неможлива, зафіксуй причину та запропонуй реальний альтернативний спосіб виконання MPI.

Створи `docs/mpi-setup.md`.

# Етап 7. Бенчмарки та оптимізація

Проведи дослідження продуктивності всіх реалізацій.

Розміри масиву:
- 1M;
- 10M;
- 100M;
- 1B.

Кількість потоків:
- 1;
- 2;
- 4;
- 8;
- кількість фізичних ядер.

Для MPI перевір доступну кількість процесів.

Вимірюй:
- час виконання;
- отриману суму;
- Speedup;
- Efficiency;
- середній час;
- медіану.

Формули:

```text
Speedup = T_sequential / T_parallel

Efficiency = Speedup / N
```

Використовуй однакові вхідні дані та seed.

Для Java виконай прогрів JVM.

Не включай генерацію масиву в час обчислень, якщо порівнюєш швидкодію саме алгоритму.

Враховуй накладні витрати потоків, синхронізації та мережевого обміну.

Підготуй:
- CSV;
- таблиці;
- графіки;
- `docs/benchmark-analysis.md`.

Не вигадуй результатів.

Якщо немає ресурсів для мільярда елементів, зафіксуй максимальний реально протестований розмір.

# Етап 9. Незалежний аудит після кожного етапу

Проведи незалежну перевірку останніх змін.

Не довіряй попереднім твердженням агента про успішність.

Перевір фактичний код.

Дай відповіді:

1. Чи відповідає реалізація початковому завданню?
2. Чи правильно реалізований алгоритм?
3. Чи справді використовуються потоки або MPI?
4. Чи правильна синхронізація?
5. Чи є приховані помилки?
6. Чи можна запустити проєкт із чистого середовища?
7. Чи відповідає README фактичному коду?
8. Чи є непідтверджені результати?

Якщо знайдеш проблему:
- вкажи файл;
- вкажи конкретний метод;
- поясни причину;
- запропонуй виправлення;
- виправ її;
- повторно запусти відповідні тести.

Не змінюй працюючий код без необхідності.

Наприкінці надай звіт із переліком знайдених проблем та їхнім статусом.

## Головне правило

Лабораторна вважається завершеною лише тоді, коли реалізації відповідають методичним вимогам, програми компілюються, доступні тести проходять, MPI реально використовується, а результати експериментів підтверджені фактичними запусками.
